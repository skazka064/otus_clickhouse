### Проблематика и Цель
Рынок Форекс генерирует огромные объемы данных в реальном времени, но для качественного прогнозирования нужна не только скорость, но и накопленная история.

### Тезис: Для решения этой задачи  разработал гибридную архитектуру, которая объединяет два подхода:

    Потоковый (Streaming): для мгновенного сбора и первичной обработки данных (Kafka).
    Пакетный (Batch): для надежного хранения и построения прогнозов (Airflow + ClickHouse).

### Главная цель: Создать автоматизированный ETL-пайплайн для прогнозирования валютных курсов и выдачи торговых сигналов (BUY/SELL/HOLD) с визуализацией в реальном времени.

### Источники данных (Sources): Два канала поступления (1 минута)

    - Потоковый источник (Kafka forex_ticks): Это магистраль для данных в реальном времени. Данные поступают из внешнего API (например, Finnhub) и непрерывно пишутся в Kafka.

    - Пакетный источник (Airflow DAG hourly): Это наш "резервный канал" и источник для исторических данных. Раз в час (расписание DAG) мы делаем запрос к внешнему API и записываем срез данных в таблицу ticks. Это гарантирует, что у нас всегда есть актуальная "точка отсчета", даже если потоковый канал временно недоступен.


### Kafka
Producer — это Python-скрипт, который работает как мост между внешним API и нашей системой.
Он постоянно слушает WebSocket Finnhub и каждое обновление курса отправляет в Kafka. 
Данные передаются в формате CSV, что упрощает их дальнейшую обработку в ClickHouse.
Bid и ask — это две ключевые цены на бирже.
Bid показывает, по какой цене мы можем продать актив, ask — по какой купить. 
Разница между ними называется спредом и является основным источником дохода брокеров.
В скрипте я искусственно создаю bid и ask, чтобы продемонстрировать эту концепцию.
